## Q1: 不可恢复的内部失败也应如实展示吗？

用户期望正常情况下后端自行完成，供应商出问题才显示异常。连接独立这个方向已确认；但供应商成功后最终写 MySQL 失败，或 Worker 崩溃导致结果不确定，也可能让历史里一直缺少回复。

**推荐答案:** 连接断开不影响任务；可以恢复的短暂内部故障由后台处理，不逐次打扰用户；供应商失败、内部故障耗尽恢复预算，以及 uncertain 都在历史中展示真实且可区分的状态。不能无限显示“生成中”，也不能把内部故障伪装成供应商故障。

已受理任务的结果由后台负责，不需要浏览器同意才能保存/ACK。错误展示只是让用户后来读历史时知道发生了什么，不重新引入前后台执行依赖。

用户答复: 接受推荐。连接断开不改变任务状态；可恢复的短暂内部故障由后台处理，不逐次打扰用户；供应商失败、内部故障耗尽恢复预算及 uncertain 均如实展示并区分归因，不伪装成功，也不无限显示“生成中”。

影响: 确定历史 API 的状态投影、错误码归因以及前端展示边界。具体重试预算、超时时间和实现表结构由后续技术设计/测量确定，不能用任意数字替代本轮语义确认。
